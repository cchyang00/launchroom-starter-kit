# Create a focused specialist workspace

Read the [registry and contract](../agents/README.md). Start from an actual recurring job. Give the role a plain name that explains what it produces; product and country variants belong beneath the product records.

## Child AGENTS content

Write a short role-specific document containing:

1. **Role:** outcome owned, related work routed elsewhere, manager relationship.
2. **Startup:** parent AGENTS, shared/local STATE, canonical skill, relevant input evidence and lessons. Resolve relative links from the new file's location.
3. **Ownership:** canonical outputs and files this worker may change; authoritative product/store records linked, not copied. External operator coordination when applicable.
4. **Finish:** observable acceptance evidence and handoff fields. Distinguish a prepared draft, saved configuration and tested result.
5. **Learning:** local lesson destination and manager integration; link the [shared improvement procedure](../agents/manager/references/IMPROVEMENT.md) and add only role-specific checks. Include next-job reuse of adopted changes.

## Files to create

- `AGENTS.md` and `memory/STATE.md`: required role/context and current handoff.
- `.agents/skills/<skill>/SKILL.md`: when a reusable specialized procedure exists. Use native skill-creator guidance and validator; define a precise name/description and read relevant references conditionally.
- `references/`: actual supporting knowledge or visual index. Preserve source files; include provenance, applicability and limits.
- `memory/LESSONS.md`: start with evidence from prior jobs if available; otherwise record that no local result exists.
- Role templates/assets/sandbox: create when the assignment needs them. Avoid empty folder trees built for speculative future work.

## Register and verify

Register exact entry paths and ownership in `agents/README.md`; add a parent pointer only for a new routing branch. Read back relative links and skill metadata. Walk a realistic task from parent routing through child output and learning; check a contrasting request goes to the appropriate other role. Record configuration checks separately from live execution. No automated launch or training is created by these files.
