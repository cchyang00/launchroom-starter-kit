# Local operations app

Parent instructions apply. Read `README.md`, `../PRODUCT.md` and the existing design contract before changes. The app is a React frontend plus native Node APIs; business folders remain the source of truth.

**Launchroom, October 1:** accounts, project routing and shared uploads wrap the existing interface. Read [the operating guide](../resources/notes/2026-10-01-launchroom-operating-guide.md) before changing access, storage, startup or remote networking. `server/launchroom.mjs` must remain before all API/static/dev middleware.

**Launchroom UI (Oct 1, os-builder; replaces Codex's `lr-` top bar and `?files=1` shell).** The owner asked for one coherent app in our visual language. `src/Launchroom.jsx` is the root: session, sign-in, setup (home computer only) and invitation screens (errors by code through `authMessage`, LS-073; passwords never prefilled or kept), the Launchroom home (`/`: Today across projects, project cards with each project's next move from its own `/p/<id>/api/pipeline` and planner, the Shared library card) and the Shared library page (`/p/shared/`) in the same dark-sidebar shell. `src/LaunchroomShell.jsx` holds `LaunchroomContext`, the project switcher (top of the sidebar; top bar on phones), the account menu (sidebar foot), People & access (invite code shown once, per-person project toggles saved per changed project, Disable with a confirm) and New project (name only). `src/FilesView.jsx` is Files (`#/files` in a project) and the Shared library: folder tiles first, thumbnails, sort, search, grid/list, breadcrumbs, New folder, drag-and-drop and Upload with a per-file progress list (portalled to `body`), the preview sheet and Removed with Restore; no permanent delete. `src/launchroomModel.mjs` holds the pure rules (marks, titles, `#/product/<id>` routing, file kinds, destinations, error words, today across projects, project summaries, access changes), tested in `server/launchroomModel.test.mjs`. Styles are `mv-lr-` in `src/launchroom.css`. App shows Merrivy's store previews and localhost:3001 links only in Merrivy (`isMerrivy`); a brand-new project's Home is a start state. The product page moved to `#/product/<id>` (the old `#/p/<id>` redirects) because `/p/` is the project path. Store previews are imported from `src/media/` so they ship under `/assets/`. `GET /p/<id>/api/files/preview` (membership-checked like download) streams only images and videos inline (sandbox CSP, nosniff, short private cache, single byte ranges) and returns `.txt/.md/.csv` as JSON text (first 64 KiB); other types stay download-only; a removed file previews only by its Removed id. Tested in `server/launchroomPreview.test.mjs`. Remote access and remote agent runs stay disabled; the UI never claims them. No screen starts a run since Nov 4; the server still allows one only from the owner's own browser (Oct 3, below). Every project request requires session and membership checks; the explicit local-agent route is reserved for trusted host CLI processes. `LAUNCHROOM_PROJECT` scopes the helper; an unavailable scoped API must never fall back to Merrivy. Account/TLS files stay under ignored `private/`, outside all readable resource roots. Remote agent execution is disabled pending a real project sandbox.
